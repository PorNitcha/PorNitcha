### Lesson Learned (07-Sep-2026 15:10)
1. **`read_resource` บน xlsx จะถูก truncate โดย sheet ซ่อนที่อยู่ก่อนหน้า** — `May (FC)` (บรรทัด 300–2355) กิน budget จนถึง `Aug —` แล้วหมดพอดี ⇒ **การอ่าน sheet ท้ายไฟล์เป็น "แพ้ตามลำดับ" ไม่ใช่ random** · รอบ 14:30 ที่อ่านได้คือรอบที่ budget เหลือพอดีเป๊ะ ⇒ ห้ามคาดหวังว่า retry จะสำเร็จ
2. **`startPage` / `endPage` ใช้ไม่ได้กับ xlsx** — ทดสอบแล้ว 3 รูปแบบให้ผลเท่าเดิม (±2 บรรทัด) ⇒ **ครั้งหน้าไม่ต้องเสีย tool call ลองซ้ำ 3 รอบ** · ลองครั้งเดียวแล้วบันทึกว่าอ่านไม่ได้ ยกเป็นงานค้าง (ประหยัด 2 tool call + ~3k token)
3. **URI แบบ path ใช้กับไฟล์นี้ไม่ได้** — `file:///{driveId}/Shared Documents/...` ตอบ NOT_FOUND (ต้องตัด `Shared Documents` ออก) ⇒ **ใช้ `file:///{driveId}/{itemId}` จาก `sharepoint_search` เท่านั้น** อย่าประกอบ path เอง
4. **เพิ่ม check "default leak scan" เข้า verify ประจำแล้ว** — scan ทั้ง CSV หา %Rec ที่เท่ากับ default ของโรงนั้นเป๊ะ (TN/PM/TDC/MS=100.0, TKT=95.0) หรือ 0.0 · รอบนี้ผ่าน 0 แถว · เป็น check ที่ดักกฎ C ได้ตรงจุดที่สุดและถูกกว่าการ re-parse ต้นทาง
5. **mtime ขยับพอดี +1 ชั่วโมง (06:26:07 → 07:26:12) น่าสงสัยว่าเป็น DST/timezone artifact** แต่วินาทีต่างกัน (+5s) ⇒ เป็นการเซฟจริง ไม่ใช่ artifact · **ถ้ารอบหน้าเจอ +1h เป๊ะทั้งวินาที ให้สงสัย timezone ก่อน ไม่ต้อง re-parse**
